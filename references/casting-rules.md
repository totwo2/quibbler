# 选角规则（casting-rules）

> **本文件的读者是主 Agent，不是人。** 全部写成可逐条执行的检查表。
> **加载时机**：判定完素材类型 `types` 之后、公示阵容之前。与 `references/roles/index.yaml` 配套使用。
> **上游数据**：`references/roles/index.yaml`（38 条精简索引，唯一选角数据源）
> **下游数据**：`references/roles/group-{a,b,c,d,e}-*.md`（只加载命中分组，提取完整角色卡）
> **输出**：`CastingPlan{roles, seat_assignment, focus_partition, rationale, max_overlap, planned_minutes, mode}`

---

## 0. 术语与字段映射（跨文件契约，逐字对齐）

### 0.1 席位短名 ↔ 长名

`index.yaml` 的 `seat` 字段用短名；`ExperienceLog.seat` 用长名。**转换是强制的，不得混用。**

| 短名（index.yaml `seat`） | 长名（Brief / ExperienceLog `seat`） | 中文席位名 | 本场配额 |
|---|---|---|---|
| `pro` | `professional_core` | 专业内核席 | 2–3 |
| `layman` | `layman` | 外行真人席 | 1–2 |
| `adversary` | `adversary` | 敌对席 | **1（必选）** |
| `edge` | `edge_user` | 边缘用户席 | **1（必选）** |
| `crossover` | `crossover` | 跨界外脑席 | 0–1 |

### 0.2 默认席位 vs 本场席位

- `index.yaml` 的 `seat` = 该角色的**默认席位**（角色固有属性）。
- `CastingPlan.seat_assignment` = 该角色**本场实际占用的席位**。
- 两者**允许不一致**，这叫**顶替**（见 §3 STEP 4）。顶替必须在 `rationale` 中写明一句理由，并在公示卡片中标注 `【顶替】`。
- 顶替不改变角色卡内容，只改变 Brief 中下发的 `{seat_type}` 与 `{seat_duty}`。

### 0.3 席位职责（写进 Brief 的 `{seat_duty}`）

| 席位 | `seat_duty` 原文（照抄进 Brief） |
|---|---|
| `professional_core` | 保证技术/专业结论站得住脚。你说的每一句行话都要能被同行验证。 |
| `layman` | 你代表那些没有背景知识就撞上这东西的人。你看不懂的地方，就是它的认知墙。 |
| `adversary` | 你的任务是预演「这东西发出去会被怎么骂」。找可被截图的黑点、逻辑漏洞、翻车点。 |
| `edge_user` | 你的使用条件被主流忽略了。你走不通的路，对你而言就是不存在的功能。 |
| `crossover` | 你不是这个行业的人。用你本行的常识去照它，照出本行看不见的东西。 |

## 1. 席位配额铁律（派发前强制校验，不是建议）

```
╔══════════════════════════════════════════════════════════════════╗
║  ⛔ CASTING GATE — 不通过不许派发，必须重新选角                     ║
║                                                                  ║
║  G1  professional_core  数量 ∈ [2, 3]                            ║
║  G2  layman             数量 ∈ [1, 2]                            ║
║  G3  adversary          数量 == 1   ← 必选，为 0 直接 FAIL        ║
║  G4  edge_user          数量 == 1   ← 必选，为 0 直接 FAIL        ║
║  G5  crossover          数量 ∈ [0, 1]                            ║
║  G6  总人数 == 目标人数（S=3 / M=6 / L=7 / --lite=3 / --full=7）  ║
║  G7  role_id 全场唯一，无重复入选                                  ║
║  G8  任意两人 Jaccard(cares_tags) ≤ 0.5                          ║
║  G9  每人 assigned_focus 长度 ∈ [3, 4] 且原标签两两不交           ║
║                                                                  ║
║  任一项 FAIL → 回到 §3 STEP 2 重新抓人，禁止「先派了再说」          ║
╚══════════════════════════════════════════════════════════════════╝
```

**G3 / G4 的执行说明**：这两席在任何素材类型下都不允许为空。若默认阵容表里没有天然人选，走 §3 STEP 4 的兜底铁律**顶替**，而不是降低配额。

**3 人模式（S 档 / `--lite`）的配额降级**（唯一被允许的配额变体）：

| 席位 | 3 人模式配额 |
|---|---|
| `professional_core` | 1 |
| `adversary` | **1（仍必选）** |
| `edge_user` | **1（仍必选）** |
| `layman` / `crossover` | 0 |

> 3 人模式砍的是专业席与外行席，**敌对席与边缘席一个都不能砍**。这两席是本技能区别于「找个专家看看」的全部价值。

### 2.3 组合类型的合并规则

`types` 含多个类型时（如 `[CODE, WEB]`）：

1. 取各类型 §2.2 阵容的**并集**作为候选集 C，各类型 §2.1+§2.2 备选池并集作为备选池 P。
2. **主类型判定**：`type_signals` 命中数最多者为主类型；平票时按 `CODE > API > WEB > DATA > DOC > NOVEL > VIDEO > DESIGN` 的固定序取第一个。主类型的 pro 席优先保留。
3. 按 §3 STEP 2 重新抓人到目标人数，**不是简单拼接**。
4. 跨类型的强关联角色优先（`material_types` 同时命中 ≥2 个本场类型者，抓人时相当于命中数 +1）。

> 例：`[CODE, WEB]` 主类型 CODE。候选并集含 A2/A1/A6/A3/D3/E8/B3/B4/D1/D2/D6/B5。
> A2 韩渗透 `m:[CODE,API,WEB]` 同时命中 CODE 与 WEB → 优先级最高的 pro。
> 最终 6 人：A3 林接盘(pro)、A2 韩渗透(pro)、A6 苏边界(pro)、D3 丁三分钟(layman)、B5 顾无碍(edge_user)、E8 卓对手(adversary)。

## 3. 选角算法 · 八步检查表

> STEP 1–7 是选人，STEP 8 是产出公示文案。每步给「怎么判断」，不给伪代码。

### STEP 1 · 建候选集

1. 读 `references/roles/index.yaml`（≤6KB，全量 38 条，一次读完）。
2. 按 §2.2 取本场 `types` 对应阵容 → 候选集 C；按 §2.1+§2.2 取备选池 → P。
3. 组合类型按 §2.3 合并。
4. **不要**在这一步读 `group-*.md`。角色卡详情要到 STEP 6 才加载（渐进披露，省上下文）。

### STEP 2 · 按席位抓人（贪心，顺序不可颠倒）

**抓人顺序：adversary → edge_user → professional_core → layman → crossover。**

> 为什么敌对席和边缘席先抓：它们是硬配额且候选面窄。最后抓必然抓不到，然后就会有人想「这次就算了吧」。先抓死它们。

| # | 席位 | 抓法 |
|---|---|---|
| 2.1 | `adversary` × 1 | 从 C 中取 `seat: adversary` 者；多于 1 人时按「与素材类型的对抗强度」取 1：素材面向公众/有舆情面 → D6 冯抬杠；素材有商业竞争面 → E8 卓对手；素材是内部文档/需求 → B1 白指标。**取不到则从 P 取，P 也没有则从全库 {D6, E8, B1} 强制拉 1 人入场，并在 rationale 写明「本类型无天然敌对角色，强制补位」。** |
| 2.2 | `edge_user` × 1 | 从 C 中取 `seat: edge` 者；多于 1 人时按素材可及性维度取 1：有视觉界面 → B5 顾无碍；有键盘交互 → D9 关无鼠；有网络加载 → D10 巴老铁；有设备性能压力 → D7 韩老机；有夜间/长时使用 → D8 苏失眠。**取不到走 STEP 4 兜底铁律顶替。** |
| 2.3 | `professional_core` × 2–3 | 从 C 中 `seat: pro` 者按 `m[]`（material_types）与本场 `types` 的**命中数降序**取；命中数相同时按 `c[]` 与素材 `type_signals` 的语义相关度取；仍平票按 id 字典序。M/L 档取 3，S 档取 1。 |
| 2.4 | `layman` × 1–2 | 从 C 中 `seat: layman` 者取。素材面向 C 端 → 优先 D1/D2/D5；素材面向开发者 → 优先 D3；素材面向企业 → 优先 D4。M 档取 1，L 档取 2。 |
| 2.5 | `crossover` × 0–1 | 仅当总人数尚未填满时取。按素材所属领域取对口 E 组角色（医疗 E1 / 财务 E2 / 教学 E3 / 客服 E4 / 销售 E5 / 采购 E6 / 媒体 E7）。填满则取 0。 |

抓完立即跑一次 CASTING GATE 的 G1–G7。

### STEP 3 · 视角重叠校验（Jaccard）

1. 对已选集合中**任意两人** a、b，用 `index.yaml` 的 `c[]` 字段计算：
   ```
   J(a, b) = |c(a) ∩ c(b)| / |c(a) ∪ c(b)|
   ```
   比较前先做标签归一（§4.2 同义表）。
2. `J > 0.5` → 判定重叠超标。**保留席位稀缺度高的一方**，替换另一方：
   - 稀缺度序：`adversary` = `edge_user` > `layman` > `professional_core` > `crossover`
   - 同稀缺度时保留 `m[]` 命中数多的一方。
3. 替换人选：从备选池 P 中取**与「已选集合去掉被换者之后」的平均 Jaccard 最小**、且 `seat` 与被换者相同（或可顶替）的角色。
4. 换完重跑本步，最多 3 轮。3 轮后仍超标 → 保留当前集合，把 `max_overlap` 如实写入 `CastingPlan`，并在公示卡片中提示「本期两位体验者视角接近，已用 focus 分区强制错开」。
5. 记录全场最大值到 `CastingPlan.max_overlap`。

### STEP 4 · 兜底铁律（顶替）

触发条件：某必选席位（`adversary` / `edge_user`）在 C 与 P 中均无 `seat` 匹配者。

| 缺失席位 | 顶替人选（按序尝试） | 顶替后 Brief 里的说法 |
|---|---|---|
| `edge_user`（纯 CODE / API 常见） | ① A3 林接盘（新人视角＝知识边缘） ② D3 丁三分钟（低耐心＝注意力边缘） ③ D9 关无鼠（纯键盘） | 「你这次坐的是**边缘用户席**。你的边缘不在身体条件，在于你没有这个项目的任何背景知识/耐心。」 |
| `edge_user`（DATA / DOC 常见） | ① B5 顾无碍（图表对比度与读屏） ② D7 韩老机（老设备打开看板） ③ D1 王阿姨（低数字素养） | 同上，按角色改写一句 |
| `adversary`（任意类型） | ① E8 卓对手 ② D6 冯抬杠 ③ B1 白指标 | 「你这次坐的是**敌对席**。」 |
| `professional_core`（冷门领域） | 从 crossover 中取领域最近者顶替 | 「你本行不是这个，但本场没有比你更近的人，请只在你确信的范围内下结论。」 |

**顶替三条约束**：
1. 顶替者的**角色卡内容一字不改**（不许为了凑席位改写人设）。
2. 顶替必须写进 `rationale`，公示卡片对应行加 `【顶替】` 标记。
3. 同一人**不得同时占两个席位**。若 A3 顶替 edge_user，则 pro 席必须另选足额。

### STEP 5 · 用户意图覆盖

| 情形 | 处理 |
|---|---|
| 用户 `--roles A1,D6` 或口头指定已有角色 | **强制入选**。挤掉「同席位中优先级最低者」（优先级 = STEP 2 的抓人排序位次）。若被指定角色导致必选席位空缺，回 STEP 2 补齐，宁可挤掉 pro 席也不能挤掉 adversary/edge_user。 |
| 用户描述一个库里没有的角色（"再加一个做跨境电商的越南买家"） | 按 §5 生成临时角色卡，`temporary: true`，占 `layman` 或 `crossover` 席（按描述判断），同样挤掉同席位最低优先级者。 |
| 用户指定人数（"就找 3 个"） | 覆盖体量档推断，按 §1 的 3 人模式配额执行。 |
| 用户排除某角色（"别叫那个律师"） | 从 C 与 P 中移除，重跑 STEP 2。 |
| 用户指定的角色与素材类型完全不搭（让 C6 江分贝 看 CSV） | **仍然入选**（用户意图优先），但在 Brief 的 `{seat_duty}` 后追加一句：「本场素材不在你的常规领域，请大量使用『我不懂这个，但我感觉不对，因为……』的表达，不要硬装内行。**「因为」后只能接你自己的经历或职业直觉，不能接技术因果解释；说不出「因为」也完全合格——把感受锚定到具体哪一步即可。**」并在公示卡片标注 `【用户指定·跨领域】`。 |

### STEP 6 · 体量调整与角色卡加载

1. 按 `MaterialProfile.size_tier` 与 CLI 开关确定目标人数：

| 档位 / 开关 | 人数 | 单角色预算 | 预计墙钟 | 公示话术 |
|---|---|---|---|---|
| S | 3 | 8 次调用 / 5 分钟 | 6–9 分钟 | "素材较小，本次召唤 3 位" |
| M（默认） | 6 | 12 次调用 / 8 分钟 | 10–15 分钟 | 默认，不额外说明 |
| L | 7 | 16 次调用 / 10 分钟 | 14–22 分钟 | "大型素材，允许分段体验" |
| `--lite` | 3 | 8 / 5 | 6–9 分钟 | "轻量模式，3 位体验者" |
| `--full` | 7 | 16 / 10 | 14–22 分钟 | "完整阵容，7 位体验者" |

   显式开关 > 体量档推断。人数变化后**重跑 STEP 2 的配额校验**（减人先减 crossover，再减 layman，再减 pro；加人反序）。
2. 统计入选者的分组前缀（A/B/C/D/E），**只 Read 命中的 `group-*.md`**（通常 2–3 个）。
3. 从每个分组文件中抽出对应小节，组装 `RoleCard`：`id / name / occupation / age / background / cares_about[] / catchphrase / tone / material_types[] / aux_skills[] / seat_type / cognitive_limits[] / signature_actions[] / temporary`。
4. **交叉核对**：角色卡的「最在意」列表必须与 `index.yaml` 的 `c[]` 一致。不一致以 `group-*.md` 为准，并在 rationale 末尾追加一行 `[索引不同步] {id}`。

### STEP 7 · 互斥 focus 分区（防重叠的执行手段）

见 §4。这是把「Jaccard ≤ 0.5」从**事后检查**变成**事前隔离**的关键一步，**不可跳过**。

### STEP 8 · 产出 rationale 与公示

1. 为每人写**一句**「为什么是他」，≤25 字，必须指向素材的具体特征，不许写「他很专业」这类废话。
   - ✅ "有 .env 和外部接口，必须过一遍"
   - ✅ "dist/ 里有前端，键盘与读屏必查"
   - ❌ "安全视角很重要"
2. 按 §6 格式输出公示卡片，等用户确认（`--yes` / `--no-confirm` 跳过）。
3. 用户回复「调整阵容」→ 按 STEP 5 处理其指定，重跑 GATE，再次公示。

## 4. 互斥 focus 分配算法（FP，可机械执行）

**输入**：本场角色列表 R，每人的 `cares_about`（4–6 条）
**输出**：每人 `assigned_focus`（3–4 条），写进 Brief 的「你最在意的事」段

### 4.0 FP-0 身份锚点：划走标签是减法，不能把角色减没了【v1.1】

```
╔══════════════════════════════════════════════════════════════════╗
║  分区是减法。减到最后可能把一个角色赖以成立的核心关注点减掉。        ║
║  顾无碍若被划走「读屏与 alt 文本」，他就只是个普通挑剔用户，        ║
║  这个席位白设了。                                                 ║
╚══════════════════════════════════════════════════════════════════╝
```

| # | 规则 |
|---|---|
| 1 | `index.yaml` 中每个角色 `c` 数组的**第 1 个元素**即**身份锚点**（identity anchor），**永不参与划走**，必定进入 `assigned_focus` 且**排在第 1 位** |
| 2 | 分区（FP-3 的贪心）**只在第 2–6 个标签之间进行**。`c[0]` 直接跳过 `claimed` 检查 |
| 3 | **若两人的身份锚点本身撞车 → 说明选角错了，回 §3 STEP 3 换人，而不是划标签。** 锚点冲突是**选角失败的信号**，不是分区要解决的问题 |
| 4 | 实现代价为零——只是给 `c` 数组的顺序赋予语义，不增加一个字节 |

> **`c` 数组顺序有语义，任何环节不得重排。** 读 `index.yaml` 时按原序取，不要排序、不要去重打乱。

**T02 已按下表设定 5 组高危撞车对的锚点**（选角时直接信任 `c[0]`，不要自己重新判断）：

| 撞车对 | 冲突标签 | 锚点分别是 |
|---|---|---|
| B5 顾无碍 vs D9 关无鼠 | 焦点顺序 ≈ Tab 顺序 | 顾无碍→「读屏与 alt 文本」；关无鼠→「键盘操作路径与焦点陷阱」 |
| D2 小李 vs D10 巴老铁 vs A4 罗火焰 | 加载速度三方重叠 | 小李→「中断后能否续上」；巴老铁→「弱网下的加载反馈」；罗火焰→「代码层复杂度与包体积」 |
| C4 秦帧 vs C5 卢完播 | 都主张"前 3 秒钩子" | 秦帧→「剪辑节奏与废镜头」；卢完播→「留存曲线与封面标题」 |
| D1 王阿姨 vs D5 沈护娃 | 都关心付费焦虑 | 王阿姨→「字号与操作可撤销」；沈护娃→「儿童安全与隐私采集」 |
| C1 何删 vs B4 邱一句 | NOVEL 下都管文字 | 何删→「结构与可删率」；邱一句→「单句措辞与报错话术」 |

**锚点撞车判定**：归一化（FP-2）后两人的 `c[0]` 相同 → 撞车。处置**只有换人一条路**：保留席位稀缺度高的一方（稀缺度序见 §3 STEP 3），另一方从备选池 P 中换成 `c[0]` 与全场已有锚点均不相同者。**不许**用加切面（FP-5）的方式糊弄过去——切面能区分次要标签，区分不了身份。

### 4.1 FP-1 定序（抢标签的优先权）

按**席位稀缺度**排序，稀缺者先挑：

```
adversary(1) → edge_user(2) → layman(3) → professional_core(4) → crossover(5)
同席位内：m[] 命中数降序 → id 字典序升序
```

> 理由：敌对席与边缘席的标签窄且独特，专业席的标签宽。让宽的先挑，窄的就没得挑了。

### 4.2 FP-2 标签归一

比较与分配前，把 `cares_about` 文本映射到规范标签。同义归并表（按需扩充，命中即替换）：

| 规范标签 | 归并的原文 |
|---|---|
| `加载速度` | 加载速度 / 首屏 / 转圈 / 卡顿 / 打开慢 / LCP |
| `错误可读性` | 报错话术 / 错误码语义 / 操作失败 / 异常路径提示 |
| `文档一致性` | 文档与实现是否一致 / README 能否跑通 / 说明书对不上 |
| `键盘可达` | 快捷键 / Tab 顺序 / 焦点陷阱 / Esc / 键盘 only |
| `对比度与字号` | 对比度 / 字大不大 / 暗色模式 / 亮度突变 |
| `输入边界` | 边界值 / 空态 / 超大输入 / 非法值 / emoji |
| `成本与回报` | 多少钱 / 预算 / 要不要专人维护 / 效果在哪儿 |
| `口径定义` | 字段口径 / 活跃用户怎么定义 / 统计陷阱 / 去重逻辑 |

未命中归并表的标签**保留原文**参与比较（字符串相等即视为同标签）。

### 4.3 FP-3 贪心分配

```
# 前置：FP-0 已确认全场锚点两两不同（撞车则已换人，不会走到这里）

claimed = ∅
# 第一轮：所有人的锚点先落袋，谁都不许抢
按 FP-1 顺序遍历 r ∈ R:
    anchor(r) = normalize(cares_about(r)[0])      # c[0]，永不划走
    assigned(r) = [ cares_about(r)[0] ]           # 原文入列，排第 1 位
    claimed = claimed ∪ { anchor(r) }

# 第二轮：在 c[1..] 里做减法
按 FP-1 顺序遍历 r ∈ R:
    pool  = normalize(cares_about(r)[1..])        # 只在第 2–6 个标签之间分区
    avail = pool − claimed
    需补 = 目标条数(3 或 4) − 1                    # 锚点已占 1 条
    若 |avail| ≥ 需补 → 从 avail 按角色卡原序取 需补 条
    若 |avail| <  需补 → 取完 avail，再从 (pool ∩ claimed) 借回差额
                          借回的标签必须按 FP-5 加切面限定
    若 |avail| = 0 且 需补 > 0 → 触发 FP-6（注意：锚点仍保住，只换次要标签或换人）
    assigned(r) += 取到的标签
    claimed = claimed ∪ normalize(取到的标签)
```

**两轮制的原因**：单轮贪心会让排序靠后的角色的锚点被前面的人抢走。锚点必须**全场先落袋**，再做减法。

### 4.4 FP-4 数量上限

每人 3–4 条。超过 4 条按角色卡原序截断到 4 条（角色卡的列表顺序即该角色的在意程度顺序）。

### 4.5 FP-5 借回改写规则

同一规范标签被两人使用时，两人的 focus 文本**必须写成不同切面**，格式 `标签｜切面`：

| 标签 | 角色 A 的切面 | 角色 B 的切面 |
|---|---|---|
| `加载速度` | D10 巴老铁：`加载速度｜4M 共享带宽下图片一张张蹦` | A4 罗火焰：`加载速度｜首屏 LCP 与包体积` |
| `错误可读性` | E4 温工单：`错误可读性｜用户看到后会不会打电话` | A5 郑对接：`错误可读性｜错误码能否被程序分支处理` |
| `输入边界` | A6 苏边界：`输入边界｜10 万字符与 emoji` | A2 韩渗透：`输入边界｜注入与越权` |

切面来源：该角色的**席位职责 + 认知边界**。改写后两人的 focus 文本**不得逐字相同**。

### 4.6 FP-6 换人条件

某角色 `avail = 0`（全部标签已被占）→ 该角色视角完全冗余。从备选池 P 中取「与已选集合平均 Jaccard 最小」且席位可匹配者替换，回 FP-3 重跑。最多 2 轮，仍不行则保留该角色但给他 3 条**全部加切面限定**的借回标签。

### 4.7 FP-7 派发前硬闸

| # | 检查 | FAIL 处置 |
|---|---|---|
| a | 每人 `assigned_focus` 长度 ∈ [3, 4] | 回 FP-3 |
| b | 任意两人 `assigned_focus` 的**规范标签**（去掉切面后）交集为空 | 回 FP-5 加切面或 FP-6 换人 |
| c | 全场 `assigned_focus` 文本两两不逐字相同 | 回 FP-5 |
| d | 借回条目总数 ≤ 全场 focus 总条数 × 20% | 回 FP-6 换人 |
| **e** | **每人 `assigned_focus[0]` == 其 `c[0]`（锚点在列且排第 1）** | 回 FP-3 第一轮 |
| **f** | **全场锚点两两不同（归一化后比较）** | **回 §3 STEP 3 换人**，禁止加切面糊弄 |
| **g** | **锚点从未出现在他人的借回列表中** | 回 FP-5，把该借回条目换成别的标签 |

**七项全过才允许进入派发。不得带病派发。**

## 5. 临时角色生成

触发：用户描述了一个角色库中没有的人（"再加一个做跨境电商的越南买家"）。

**生成模板**（字段与 `RoleCard` 逐字一致，缺一不可）：

```yaml
id: T1                      # 临时角色用 T1/T2/T3，与 A–E 主键不冲突
name: 阮进货                 # 中文姓名，姓氏可体现地域
occupation: 跨境电商买手
age: 34
background: 一句话处境，必须包含「他为什么会碰到这个素材」
cares_about: [4–6 条, 必须是这个职业真实会在意的具体事, 不许写"用户体验"这种大词]
catchphrase: 一句口头禅，带这个职业的语言习惯
tone: 语气三词，如「急躁、算账快、不绕弯」
material_types: [WEB, DATA]  # 从 8 类中选
aux_skills: [agent-browser]  # 从已装技能中选，没有就空数组
seat_type: layman            # 五选一
cognitive_limits: [他不懂什么, 遇到不懂时的正确说法]
signature_actions: [3–5 条这个角色特有的体验动作]
temporary: true              # 恒为 true
```

**生成三条纪律**：
1. `cognitive_limits` **必须非空**。临时角色最容易被写成全知全能，那就废了。
2. `cares_about` 要具体到能被验证（"越南本地支付方式有没有" 而不是 "支付体验"）。
3. 生成后立即参与 §3 STEP 3 的 Jaccard 校验和 §4 的 focus 分区，**不享受豁免**。

**报告标注**：临时角色的所有出场位置加 `[临时角色]` 前缀；末版《更正与声明》登记「本期含临时角色 T1 阮进货，由用户描述即兴生成，其视角未经角色库校准」。

**持久化询问**：报告输出后问一句「要把 T1 阮进货 存进角色库吗？」——用户同意才写入 `roles/group-*.md`，**不主动改角色库文件**。

## 6. 公示卡片格式（派发前必出，等确认）

```
📰 《唱唱反调》即将开印

素材：{material_name}（{types}，{size_tier} 档，{scale_desc}）
本期阵容（{n} 位）：
  · {id} {name}  {occupation}   {席位中文名} —— {rationale 一句}
  ...（每人一行，席位名对齐）
环境：{env.missing 摘要}（{对本次的影响}）
预计：{planned_minutes}，约 {n} 个子代理 × {budget_tool_calls} 次工具调用
产物：{workspace_relative_path}

开印吗？（回复"开"或调整阵容；下次可用 --yes 跳过本确认）
```

**格式硬要求**：
- 席位名用中文全称，`敌 对 席` 用中间加空格对齐到 5 字宽，视觉上和其他席位对齐。

- `env.missing` 若与本次素材类型无关，写「（本次不涉及，无影响）」；若有关，必须写明「相关结论将标 🔴」。
- **不得省略公示直接派发**，除非 `--yes` / `--no-confirm`。

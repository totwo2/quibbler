# 素材类型判定与体验关键动作

> **本文件的读者是主 Agent。** `inspect_material.mjs` 只吐**信号**，判型是你的活。
> 读完本文件你要产出三样东西：`types[]`（可多值）、`size_tier`（S/M/L）、`key_actions[]`（写进每份 Brief）。

---

## 1. 判定流程（四步，按顺序执行）

1. **收信号**：跑 `node scripts/inspect_material.mjs "<路径或URL>"`，拿到 `type_signals` / `ext_histogram` / `entrypoints` / `duration_s`。
2. **命中打分**：对照 §2 的信号表，每类素材数命中条数。
3. **定 types**：命中 ≥1 条**强信号**即入选；只命中弱信号且无强信号时入选但标注"次要类型"。**允许多类型并存**——"一个带前端的开源仓库" = `[CODE, WEB]`。
4. **定档 + 取动作**：用 §3 表定 `size_tier`（脚本已给建议档，你可依据"用户实际让我看什么"上下调一档，调整必须写进公示卡的选角理由）；再从 §4 取对应类型的关键动作，**去重合并**。

**判不准怎么办**：`types` 为空或两类得分接近且互斥（如 NOVEL vs DOC）→ **停下来问用户一句**，别猜。这一问的成本远低于选错 6 个人。

---

## 2. 八类素材的识别信号

信号分**强**（单条即可定类）/**弱**（需 ≥2 条或有强信号佐证）。

### CODE · 代码仓库 / 脚本

| 强 | `package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` / `pom.xml` / `composer.json` / `Gemfile` / `.git` 存在；用户直接贴了 ≥30 行代码 |
| 弱 | `ext_histogram` 中源码扩展名（`.ts/.py/.go/.rs/.java/.js`…）占比 >40%；`Makefile` / `Dockerfile` / `tsconfig.json` 存在 |

### WEB · Web 应用 / 页面

| 强 | 输入是 `http(s)://` URL 且 `content-type` 含 `text/html`；`index.html` / `dist/index.html` / `build/index.html` 存在 |
| 弱 | `vite.config.*` / `next.config.*` / `nuxt.config.*` / `angular.json` 存在；`package.json:scripts.dev` 或 `scripts.start` 存在；`html:<form>` / `html:<input>` 信号非零 |

### VIDEO · 视频

| 强 | 文件扩展名 ∈ `.mp4/.mov/.mkv/.avi/.webm/.flv/.m4v`；`duration_s` 非空且 >10 |
| 弱 | 存在 `.srt/.vtt/.ass/.lrc` 字幕文件；`media-files:N` 信号 N ≥1；用户给的是视频平台链接 |

### NOVEL · 小说 / 长文

| 强 | 单个 `.txt/.md/.docx/.epub` 且 `words` >3000 且无代码块结构；文本中出现"第 X 章"章节标记 |
| 弱 | `binary-doc-files` ≥1 且用户措辞含"读者/弃读/开头/章"；`.md` 文件占比高但无任何构建标记文件 |

### DOC · 产品文档 / PRD / 说明书

| 强 | 文件名或首行标题含 `PRD` / `需求` / `设计文档` / `说明书` / `Spec` / `RFC` / `手册`；用户明说"评审" |
| 弱 | `README.md` / `CHANGELOG.md` / `docs/` 为主体且无源码；`.docx/.pdf` 单文件且 `words` 在 500–20000 |

### DESIGN · 设计稿 / 图片

| 强 | 扩展名 ∈ `.fig/.sketch/.psd/.xd`；`image-files` ≥1 且用户措辞含"设计稿/UI/视觉/界面" |
| 弱 | 目录中 `image-files` >5 且无源码文件；单张 `.png/.jpg` 且尺寸像页面截图 |

### API · API / SDK

| 强 | `openapi.yaml/json` / `swagger.yaml/json` / `postman_collection.json` 存在；文档中出现 `GET /` `POST /` 路由表 |
| 弱 | `package.json` 声明为 library（有 `main`/`exports` 无 `scripts.dev`）；文档含"接入/鉴权/AppKey/限流/回调" |

### DATA · 数据报表 / 看板

| 强 | 扩展名 ∈ `.csv/.tsv/.xlsx`；内容是 SQL 查询 + 结果表；BI 平台链接 |
| 弱 | `.md` 中表格行数 >30 且列名含指标名（`UV/PV/GMV/留存/转化`）；图表截图 + 用户措辞含"数据/口径/周报" |

### 组合类型速查

| 现象 | 判定 |
|---|---|
| 仓库里有 `package.json` + `dist/index.html` | `[CODE, WEB]` |
| 仓库里有 `openapi.yaml` + 源码 | `[CODE, API]` |
| 一个 PRD 里嵌了大量接口定义 | `[DOC, API]` |
| 视频 + 配套字幕 + 文案稿 | `[VIDEO, NOVEL]`（文案按长文体验） |
| 数据看板网页 | `[WEB, DATA]` |

**上限：一次最多取 3 个类型。** 超过 3 个说明素材边界没划清，回去问用户"这次你最想让我看哪一块"。

## 3. 体量分档（S / M / L）

`inspect_material.mjs` 已按下表给出 `size_tier` 建议与 `tier_reason`，取**所有可用指标中的最高档**。

| 指标 | S | M | L |
|---|---|---|---|
| 行数 `lines` | < 2,000 | 2,000 – 50,000 | > 50,000 |
| 字数 `words` | < 3,000 | 3,000 – 80,000 | > 80,000 |
| 时长 `duration_s` | < 180 | 180 – 1,800 | > 1,800 |
| 字节 `bytes` | < 100 KB | 100 KB – 20 MB | > 20 MB |

**档位决定的三件事**：

| 档 | 角色数 | 单角色预算 | 预计墙钟 |
|---|---|---|---|
| S | 3 | 8 次工具调用 / 5 分钟 | 6–9 分钟 |
| M | 6 | 12 次工具调用 / 8 分钟 | 10–15 分钟 |
| L | 7 | 16 次工具调用 / 10 分钟 | 14–22 分钟 |

**极小素材护栏（PRD N3）**：`lines < 30` 或 `words < 200` 或"单个静态图标"→ **不要召唤 6 个人**。降级为 1–2 角色的单人快评，并明确告诉用户"素材太小，多角色是浪费"。

**L 档的分段建议**：v1 不做自动切分。在 Brief 里给每人一个 `scope_hint`（如"只看 src/core"），靠 focus 分区自然错开覆盖面。

## 4. 各类素材的「体验关键动作」

> 下列清单直接摘录进子代理 Brief 的 `{key_actions}` 段。每类取 **5 条左右**，与角色的 `signature_actions` 合并后去重。
> 若某条动作命中 `preflight.mjs` 的 `forced_red_scopes`，**在 Brief 中原样保留但标注「本机不可执行，必须标 🔴」**——不要偷偷删掉，删掉就等于掩盖覆盖缺口。

### CODE

1. **只看 README 按步骤装一遍**，计时到"第一次跑起来"（或第一次失败）。
2. 真实执行 `install` / `build` / `test` / 主入口，逐条记录**命令 + 退出码 + 耗时**。
3. 故意传错参数、空输入、超大输入、非 UTF-8 输入。
4. `Grep` 硬编码密钥、`TODO`、`FIXME`、`console.log` 残留。
5. 随机挑 1 个函数，尝试口述其作用，测可读性（说不出来就是可读性问题）。

### WEB

1. 用 `agent-browser` 真实打开，截首屏，记录**从回车到可交互的秒数**。
2. 完成一条完整主任务链（如 注册 → 创建 → 保存 → 刷新后还在不在）。
3. 移动端视口 / 慢网（3G 节流）/ 键盘-only 各走一遍。
4. 表单填非法值、连点提交、中途刷新、后退键。
5. 记录每一步耗时与卡顿，截图存 `evidence/{ROLE_ID}/NN-*.png`。

### VIDEO

1. 抽帧看前 3 秒 + 每 10 秒关键帧（`ffmpeg`）。
2. 提取音轨转写字幕，或直接读现有 `.srt/.vtt`。
3. 按时间轴标注注意力衰减点（哪一秒你想划走）。
4. 检查音画同步、响度突变、字幕遮挡关键画面。
5. **静音看一遍**，测视觉自解释性。

> ⚠️ 本机若无 `ffmpeg/ffprobe`，第 1、2、4 条落入 `forced_red_scopes`，只能 🔴。第 3、5 条仍可做（凭肉眼与现有字幕）。

### NOVEL

1. **完整读完，不许跳读**（跳读了就在 `degradation_reasons` 里如实写）。
2. 记录每一处"想弃读"的段落位置与原因。
3. 标注情绪峰谷，对应到具体段落。
4. 检查人物设定、时间线、称谓的一致性（前后矛盾处引原文行号）。
5. **只读前 300 字**，先写下"我会不会继续读"，再往下读，最后回看这个判断准不准。

### DOC

1. **照着文档试着做一次**——做不成的地方就是文档的洞。
2. 找出无法证伪的表述（"提升体验""更加高效"这类）。
3. 检查目标是否可度量、优先级是否存在、验收标准是否写了。
4. 模拟评审提问 5 个，且必须是文档里答不上来的问题。
5. 检查术语首次出现时有没有解释。

### DESIGN

1. **3 秒扫一眼**，立刻说出"这是什么页面、我该点哪"，再对答案。
2. 测对比度（正文与背景）与最小可点区域（<44px 记一笔）。
3. 想象所有文案膨胀 40%（德语/长中文名）后的样子。
4. 检查空态 / 错误态 / 加载态 / 禁用态是否被设计过。
5. 找出视觉层级与信息优先级不一致的地方。

### API

1. 照文档写一段最小可运行客户端，**真的发一次请求**。
2. 故意触发 4xx / 5xx，看错误码语义是否可自愈（能不能凭错误信息自己修好）。
3. 检查鉴权流程步数、限流说明、分页语义（游标还是页码，边界怎么办）。
4. 对比类型定义与实际返回是否一致（字段名、可空性、时间格式）。
5. 数一数"从零到第一次成功调用"需要读几处文档、跳几个页面。

### DATA

1. **复算 1–2 个关键指标**，验证能否复现（复现不出来就是致命伤）。
2. 逐字段追问口径定义（"活跃用户"到底怎么算）。
3. 检查空值 / 时区 / 单位 / 精度 / 去重逻辑。
4. 用这份图表讲一个完整故事，看能不能讲通。
5. 找一个"看起来对但其实误导"的呈现（截断的 Y 轴、饼图超过 7 项、双轴对比）。

---

## 5. 通用前置动作（所有类型共用）

无论什么类型，每个子代理在 DXP 第 2 步之前都要做完这三件事：

1. 读 `MaterialProfile` 里的规模数字，先在心里有个体量预期。
2. 确认自己**能不能真的访问到素材**——访问不了立刻在 `degradation_reasons` 记一笔，别硬撑着推演。
3. 确认 `forced_red_scopes` 里有没有跟自己关键动作重叠的项——有就提前知道哪几条注定是 🔴。

## 6. 判型结果的落地格式

判完写进 `meta.json` 与公示卡，格式固定：

```
types: [CODE, WEB]
size_tier: M（18,422 行 → M；4.6 MB → M；取最高档 M）
key_actions:
  - [CODE] 只看 README 装一遍并计时到第一次跑起来
  - [CODE] 真跑 install/build/test，记录退出码
  - [CODE] 传错参数 / 空输入 / 超大输入
  - [WEB]  agent-browser 打开 dist/index.html 截首屏
  - [WEB]  键盘-only 走一遍主任务链
```

每条动作**必须带类型前缀**，子代理据此知道自己在为哪个维度负责。

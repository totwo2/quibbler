# 报告版式模板 ——《唱唱反调》9 版面骨架

> **本文件是 `report.md` 的唯一版式真源。** 主 Agent 按此生成，`scripts/verify_report.mjs` 按此校验。
> **两条不可动的东西**：① §1 的 H2 锚点文字（逐字，含 emoji 与空格）；② §3 的机器标记注释（`<!-- QUIBBLER:... -->`）。
> 内容算法见 `synthesis-rules.md`；指标口径见 `dxp-protocol.md` §5。本文件只管"长什么样、填在哪"。
> 基调：**栏目名有报纸味，正文必须是高信息密度的可执行内容。** 为了幽默牺牲可用性 = 版式失败。

---

## 1. H2 锚点契约（**逐字固定，改一个字符就是违约**）

`report.md` 必须且只能包含以下 10 个 H2。**顺序不可调换，一个都不许少**（无内容也保留标题，见 §5 空版规则）。

| # | 类别 | H2 锚点原文 | emoji 码点 |
|---|---|---|---|
| 0 | 报头 | `## 📰 刊号栏` | U+1F4F0 |
| 1 | 版面 | `## 🗞 头版头条` | U+1F5DE |
| 2 | 版面 | `## ⚰️ 讣告版 · 致命伤` | U+26B0 U+FE0F |
| 3 | 版面 | `## 📢 社论 · 众口一词` | U+1F4E2 |
| 4 | 版面 | `## ⚔️ 争鸣版 · 唱唱反调` | U+2694 U+FE0F |
| 5 | 版面 | `## ✉️ 读者来信` | U+2709 U+FE0F |
| 6 | 版面 | `## 💎 遗珠版 · 被低估的亮点` | U+1F48E |
| 7 | 版面 | `## 🌡 天气预报 · 风险预测` | U+1F321 |
| 8 | 版面 | `## 📋 分类广告栏 · 急聘修复` | U+1F4CB |
| 9 | 版面 | `## ⚖️ 更正与声明` | U+2696 U+FE0F |

> **`sections_present` 计数口径**：`#1–#9` 共 **9 个版面**（`#0 刊号栏` 是报头，单独校验，不计入 9）。
> `ReportMetrics.sections_present` 满分为 `9`，`sections_missing[]` 填缺失锚点的**原文**。

**给 `verify_report.mjs` 的匹配规则（避免 emoji 变体选择符踩坑）**：

1. 逐行取以 `## ` 开头的行；
2. 对该行与锚点表原文**同时**做归一化：删除全部 `U+FE0F`（变体选择符）→ 把连续空白折叠为单个半角空格 → `trim()`；
3. 归一化后做**全等比较**，不要用 `includes`（防止子串误命中）；
4. 命中的 H2 之间的内容即该版正文，用于后续的证据标签扫描与 P0 红线检查。

## 2. 占位符字典

`{{...}}` 一律**双花括号 + 全大写下划线**，正则 `\{\{[A-Z0-9_]+\}\}`。

### 2.1 机器回填位（**模型禁止手写，一律由 `verify_report.mjs` 回填**）

| 占位符 | 值示例 | 来源 |
|---|---|---|
| `{{REAL_EXEC_RATE}}` | `35%（12/34）` | `dxp-protocol.md` §5.1。**渲染为百分比+分数**（JSON 里存 `0.35`） |
| `{{REAL_EXEC_BADGE}}` | `⚠️ 环境受限` / `✅ 无环境限制` | `excusable_red > 0` 时前者 |
| `{{DILIGENCE_RATE}}` | `92%（12/13）` / `不适用` | `dxp-protocol.md` §5.2。**`null` 时渲染 `不适用`** |
| `{{DILIGENCE_BADGE}}` | `✅ 可执行范围内已尽责` / `❌ 低于 85% 门槛` / `— 本次无可执行范围` | 按门槛与 `null` 三态 |
| `{{GREEN_COUNT}}` | `12` | 计数域内 `green` 条目数 |
| `{{YELLOW_COUNT}}` | `3` | 计数域内 `yellow` 条目数 |
| `{{RED_COUNT}}` | `19` | 计数域内 `red` 条目数 |
| `{{EXCUSABLE_RED}}` | `21` | `cause ∈ {env_missing, access_denied, not_applicable}` 的 🔴 条数 |
| `{{TOTAL_CONCLUSIONS}}` | `34` | 计数域总条数，恒等于 green+yellow+red |
| `{{ENV_MISSING}}` | `ffmpeg / ffprobe` / `无` | `EnvProbe.missing`，` / ` 连接 |
| `{{INSTALL_HINTS}}` | `winget install Gyan.FFmpeg` | `EnvProbe.install_hints`，多条换行缩进对齐 |
| `{{AFFECTED_ROLES}}` | `C4 秦帧（纯推演）、C6 江分贝（纯推演）` / `无` | 因环境缺失而降级的角色 |
| `{{COVERAGE}}` | `26/32` | `dxp-protocol.md` §5.3，分数形式，**不转百分比** |
| `{{ISSUE_NO}}` | `007` | 扫 `.quibbler/reports/` 已有目录数 +1，三位补零 |
| `{{VERIFY_STATUS}}` | `通过` / `通过（2 项已修正）` | verify 退出码 |
| `{{VERIFY_TIME}}` | `2026-08-07T22:14:03+08:00` | ISO 8601 |

> **三条渲染红线**（`verify_report.mjs` 实现时必须照做）：
> 1. `diligence_rate == null`（`total_conclusions − excusable_red == 0`）时，`{{DILIGENCE_RATE}}` 渲染 **`不适用`**，`{{DILIGENCE_BADGE}}` 渲染 **`— 本次无可执行范围`**。**不许渲染 `0%`（冤枉技能），不许渲染 `100%`（粉饰太平）。**
> 2. 真实执行率**不设下限**，再难看也如实渲染，靠 `{{REAL_EXEC_BADGE}}` 与环境徽章向用户解释原因，**不许美化数字**。
> 3. 尽责率 < 85% 时 `{{DILIGENCE_BADGE}}` 必须是 `❌ 低于 85% 门槛`，且 verify 报 `LOW_DILIGENCE` + 退出码 1。**这个红叉必须让用户看见**，它指控的是技能本身，不是用户的环境。

## 3. 机器标记注释（HTML 注释，渲染不可见，脚本必需）

| 标记对 | 包住什么 | 谁用 |
|---|---|---|
| `<!-- QUIBBLER:METRICS:BEGIN -->` … `<!-- QUIBBLER:METRICS:END -->` | 刊号栏内的指标表 | verify 定位回填 |
| `<!-- QUIBBLER:CASTING:BEGIN -->` … `<!-- QUIBBLER:CASTING:END -->` | 刊号栏内的阵容表 | verify 核对角色数与 evidence 目录一致 |

## 4. 逐版模板与填写规则

### 4.0 报头 · `## 📰 刊号栏`

````markdown
# 《唱唱反调》第 {{ISSUE_NO}} 期

```
╔══════════════════════════════════════════════════════════╗
║              《唱唱反调》 THE QUIBBLER                    ║
║   第 {{ISSUE_NO}} 期 · {{REPORT_DATE}} · 本报独家深度体验   ║
╚══════════════════════════════════════════════════════════╝
```

## 📰 刊号栏

**本期素材**：{{MATERIAL_NAME}} · {{MATERIAL_TYPES}} · {{SIZE_TIER}} 档 · {{MATERIAL_SCALE}}
**素材位置**：`{{MATERIAL_SOURCE}}`
**体验模式**：{{MODE}}　|　**环境**：{{ENV_NOTE}}

<!-- QUIBBLER:CASTING:BEGIN -->
**本期阵容（{{ROLE_COUNT}} 位）**

| 角色 | 职业 | 席位 | 为什么是他 |
|---|---|---|---|
{{CASTING_ROWS}}
<!-- QUIBBLER:CASTING:END -->

<!-- QUIBBLER:METRICS:BEGIN -->
**本期公信力指标**（由 `verify_report.mjs` 机器计算，非人工估算）

```
真实执行率：{{REAL_EXEC_RATE}}   {{REAL_EXEC_BADGE}}
尽责率：    {{DILIGENCE_RATE}}   {{DILIGENCE_BADGE}}
环境缺失：  {{ENV_MISSING}}
            → {{INSTALL_HINTS}}
受影响角色：{{AFFECTED_ROLES}}
```

| 指标 | 数值 | 说明 |
|---|---|---|
| **真实执行率** | **{{REAL_EXEC_RATE}}** | 🟢 实测结论 / 全部结论条目。**不设下限，如实呈现** |
| **尽责率** | **{{DILIGENCE_RATE}}** | 🟢 / （全部结论 − 可免责推演）。**门槛 ≥85%** |
| 证据构成 | 🟢 {{GREEN_COUNT}} · 🟡 {{YELLOW_COUNT}} · 🔴 {{RED_COUNT}}（共 {{TOTAL_CONCLUSIONS}} 条） | 计数域见 dxp-protocol §5.0 |
| 其中可免责推演 | {{EXCUSABLE_RED}} 条 | 环境缺失 / 权限受限 / 不适用；**预算耗尽不计入** |
| **覆盖度声明** | **{{COVERAGE}}** | 已执行动作 / 计划动作 |
| 有效人次分母 | {{VALID_ROLE_COUNT}} / {{ROLE_COUNT}} | 扣除未完成与纯推演角色 |
| 降级情况 | {{DEGRADATION_SUMMARY}} | 按 `cause` 分组详见《更正与声明》 |
| 体检 | {{VERIFY_STATUS}} · {{VERIFY_TIME}} | — |
<!-- QUIBBLER:METRICS:END -->
````

**填写规则**
- `{{CASTING_ROWS}}` 每行：`| A3 林接盘 | 后端工程师（新人） | 专业内核席 | 你这仓库最先接手的人就是他 |`。「为什么是他」取 `CastingPlan.rationale` 中该角色那句，**≤25 字**。
- 临时角色在角色名后加 `[临时角色]`。
- 指标区**保持 `{{...}}` 原样交付给 verify**，主 Agent 手填指标 = 违反共享红线第 7 条。
- **双指标是给两个不同对象看的，不许合并成一个数**：真实执行率回答用户的「这报告能信几分」，尽责率回答技能的「你有没有偷懒」。混成一个数，用户看到 35% 时会去骂技能，而真正该做的是装 ffmpeg。
- 环境三行（`{{ENV_MISSING}}` / `{{INSTALL_HINTS}}` / `{{AFFECTED_ROLES}}`）在**无环境缺失**时，三行值分别渲染为 `无` / `—` / `无`，**整块保留不删**——"本次无环境限制"本身是一条对用户有用的信息。
- 代码块中的对齐空格用于视觉对齐，verify 回填后**允许列宽变化**，不做严格对齐校验。

### 4.1 `## 🗞 头版头条`

```markdown
## 🗞 头版头条

# 「{{HEADLINE}}」

- {{SUB_1}}
- {{SUB_2}}
- {{SUB_3}}
```

**填写规则**
- `{{HEADLINE}}` ≤30 字、可证伪的陈述句。正反例见 `synthesis-rules.md` §8。
- 三句副标题**各含一个量化事实**（人数 / 时长 / 比例 / 次数），且必须能在正文找到出处。
- 建议配比：1 句讲最痛的共识，1 句讲最硬的数据，1 句讲被低估的亮点（**给决策者只读这一段也够用**）。
- 本版**不得**出现证据标签 emoji（保持头条干净），细节留给下面各版。

### 4.2 `## ⚰️ 讣告版 · 致命伤`

```markdown
## ⚰️ 讣告版 · 致命伤

> 以下问题会直接导致用户流失、上线事故或公关翻车。本版不含推演条目。

### 1. {现象一句话，陈述句}

- **死因**：{可观测事实}
- **报告人**：{角色名 · 职业}（{N} 人独立发现）
- **证据**：🟢 `{命令}` 退出码 {N} → [`evidence/A3/01-npm-install.log`](evidence/A3/01-npm-install.log)
- **后果推演**：{谁 · 什么场景 · 损失什么 · 频率}
- **抢救方式**：见《分类广告栏》第 {N} 条
```

**填写规则**
- **语气冷峻**：短句、陈述、不用感叹号、不抖机灵。这一版的可信度来自克制。
- 1–3 条，遴选与排序见 `synthesis-rules.md` §4。
- **🔴 条目一律不得出现在本版**；🟡 破格入选需在证据行后加 `（证据未完全闭合）`。
- 每条的 artifact 用 Markdown 链接写成**相对 `report.md` 的相对路径**，`/` 分隔。
- **空版处理**：`> 本期无讣告。这不代表它没问题，只代表没有问题严重到能杀死它。`

### 4.3 `## 📢 社论 · 众口一词`

```markdown
## 📢 社论 · 众口一词

> 本版人次分母为 {{VALID_ROLE_COUNT}} 位有效体验者（{N} 位因未完成/纯推演不计入）。

### 共识 1 · {问题标题}　🟢（3 人中 2 人实测）　**提及 3 人次**

**提及者**：林接盘 · 丁三分钟 · 苏边界

> 「这函数三百行，我不敢动。」——林接盘
> 「有没有复制粘贴就能用的？没有我就换一个库了。」——丁三分钟
> 「我先输入个 emoji 试试——它把整个进程带崩了。」——苏边界

**综合判断**：{主编一句话，这里允许用形容词}
```

**填写规则**
- 按提及人次降序；人次相同按 `green` 占比降序。
- **原话逐字引用，禁止改写角色语气**——这是本报可读性的唯一来源。
- 合并证据等级取簇内最高，括号里注明构成（如 `🟢（3 人中 2 人实测）`）。
- 目标 ≥3 条；不足时按 `synthesis-rules.md` §2.3 放宽粒度重试一次，仍不足则在版尾说明。
- **空版处理**：`> 本期无共识问题——六个人吐槽的点完全不重叠，详见争鸣版。`

### 4.4 `## ⚔️ 争鸣版 · 唱唱反调`

```markdown
## ⚔️ 争鸣版 · 唱唱反调

### 分歧 1 · {争的是什么，一句话}

| 立场 | 角色 | 原话 | 证据 |
|---|---|---|---|
| **正方** | 顾无碍 · 无障碍顾问（边缘用户席） | 「我 Tab 了 14 次都走不到那个按钮。」 | 🟢 |
| **反方** | 卢完播 · 短视频运营（敌对席） | 「键盘用户占比不到 1%，先保完播率。」 | 🟡 |

- **分歧根源**：用户分层不同 —— {展开一句}
- **主编裁决**：{判正方 / 判反方 / 此题无解，取决于你的目标用户} —— {依据}
- **对下游的影响**：{是否改变某条修复项优先级}
```

**「解释 vs 体感」型分歧（D-D）专用格式 —— 裁决话术固定，一字不改**

```markdown
### 分歧 2 · 那个弹窗到底有没有问题　🛡 **直觉权威条目**

| 立场 | 角色 | 原话 | 证据 |
|---|---|---|---|
| **技术侧** | 韩渗透 · 应用安全工程师（专业内核席） | 「那个弹窗是正常的证书提示，没有风险。」 | 🟢 |
| **体感侧** | 王秀琴阿姨 · 退休小学教师（外行真人席） | 「我以为中毒了，所以我把它关掉了。」 | 🟢 |

- **分歧根源**：信息不对称 —— 一方知道那是证书提示，另一方只看到一屏英文。
- **主编裁决**：

  > 「**技术上无风险 ≠ 体验上无伤害。此处需要的不是解释，是改文案。**」

- **对下游的影响**：本条以「证书提示被误认为病毒，用户主动退出」进第 9 版，定级 P0（首次使用即流失）。
```

**填写规则**
- **必须真的把两方摆出来对撞**，不许写成"双方都有道理"。前三类（D-A/D-B/D-C）裁决三选一，必须给依据。
- 分歧根源从五选一：`用户分层` / `使用场景` / `时间尺度` / `利益立场` / `信息不对称`。
- 选「此题无解」时必须写清「主力用户是 X 听正方，是 Y 听反方」。
- **D-D 型（解释 vs 体感）适用 `synthesis-rules.md` §3.3，规则与上面三类不同**：
  - 标题行末尾加 `　🛡 **直觉权威条目**` 作为视觉标记；
  - 表格左列写 `技术侧` / `体感侧`，**不写"正方/反方"**——这不是一场需要分胜负的辩论；
  - **裁决话术逐字固定**为「技术上无风险 ≠ 体验上无伤害。此处需要的不是解释，是改文案。」，**不许改写、不许加前后缀、不许换成三选一**；
  - **双方原话必须并列**，禁止只保留专业方；
  - **禁止**出现「用户理解有误」「用户认知偏差」「该用户不具代表性」这类消解性表述。
- 若某角色全部结论均诉诸直觉权威，在其首次出现处按 §3.3.5 加注：
  `> ⚠️ **该角色本次未提供可操作信息** —— 全部结论均为主观反应，无可定位现象。其体感依然成立，但无法转化为修复项。`
- **空版处理**：`> 本期六位体验者未出现实质分歧——这不是好消息，通常意味着问题过于显眼，以至于无人有余力争论细节。`

## 5. 通用规则

### 5.1 空版处理

任何一版无内容时：**保留 H2 锚点原文**，正文写该版专属的空版话术（见 §4 各版「空版处理」）。
禁止删版、禁止合并版面、禁止写"（无）"了事——空版本身是一条信息，要说清为什么空。

### 5.2 证据标签渲染

| JSON 枚举 | 报告渲染 | 出现位置 |
|---|---|---|
| `green` | `🟢[实测]`（表格内可简写 `🟢`） | 讣告 / 社论 / 争鸣 / 读者来信 / 分类广告 |

| `red` | `🔴[推演]` / `🔴` | 同上，**但 P0 行禁止** |

头版头条与刊号栏的指标表以外，**不在报头出现证据标签**。

### 5.3 路径与链接

- 报告内所有引用一律**相对 `report.md`**，`/` 分隔：`evidence/A3/01-npm-install.log`。
- artifact 用 Markdown 链接写出，便于 verify 提取校验存在性。
- 绝对路径只允许出现在刊号栏的 `{{MATERIAL_SOURCE}}` 一处。
